# 1.0.1 身体转向补充（2026-10-22）

本次基于已验证的手腕／手臂深度版本修改。没有更换模型、改动 Unity 模型、修改 release_1_0_0 或访问训练机。

## 已确认的原因与改动

- 当前 Runner 使用 `--rgb-arm-depth-only`，原代码在该模式下强制禁用身体转向。因此即使 MediaPipe 推出了三维肩髋，Hips 仍始终朝正面。
- 本地已有 `pc/models/pose_landmarker_full.task`，已有肩线、髋线和躯干上方向构建身体坐标系的代码。本次复用这些信息，新增 `--rgb-body-turn`，无需下载其他模型或 GitHub 项目。
- 新模式只补充髋部绕 Unity Y 轴的朝向，按当前镜像坐标转换修正符号。保留 NPU 四肢二维方向、现有 RGB 手臂深度、手指和表情算法。没有启用旧版全三维四肢覆盖和深度起始姿态校准。
- 髋部旋转后，逆变换上臂局部旋转，保留原有手臂和前臂在相机空间中的完整目标坐标系，避免手臂、手腕重复旋转。腿部的平面弯曲改在旋转后的坐标系表达，保留投影方向，同时脚部随身体朝向转动。
- 反向的肩线、眼线按无向直线处理，避免将背向误读为约 180° 侧倾；侧向时减弱不可靠的肩线侧倾。正面姿态输出与原保守模式一致。
- 转向独立校验双肩和双髋，与 NPU 投影位置、来源地址、source_id 和采集时间配对。手肘／手腕遮挡不会单独导致转向失效。超过默认 150ms 的 RGB 与 DMV 时间差仍拒绝使用。
- 暂时无法估计转向时保留最后可信朝向，不再因遮挡自动回正。初始没有可信朝向时仍朝正面。单次大于 90° 的跳变需三次不同 RGB 观测确认，再使用原有速度限制及平滑，防止一帧左右标签错误造成瞬间翻转。

## 验证结果与边界

已通过 154 项 runtime Python 检查、5 项 Runner 兼容性检查，覆盖前／侧／背及连续 360° 转向、镜像模式、标签跳变、无手腕时的躯干关联、正面输出不变、转身后手臂和手腕坐标等。Unity 实际模型检查包含 52 个姿态及 62 个手掌边缘方向，结果见同目录 `body_turn_validation_20261022.json`。离线 JPEG + 合成匹配 NPU 数据的隔离 UDP 检查也通过，真实模型推理能产生非零 body_yaw 和可信 turn_conf。这些是离线集成／几何结果，不是现场转身准确率。

单目模型的深度仍是推测。完全背向、肩髋被挡或快速旋转可能跟踪失败；连续错误的三维结果也可能通过检查。转向丢失时保持旧朝向是稳定性取舍，不代表已知道当前真实方向。突发大角度变化的确认会增加两个 RGB 观测间隔的等待，普通渐进转身不受此确认门槛影响。本次没有改动原有平滑参数，也没有新增推理模型。

本次不新增腿部真实深度、身体前后俯仰、独立头部三维转向或世界空间位移。背向时 NPU 可能丢失手指／脸等不可见点，无法靠转向算法恢复；手臂深度失效后的原有短时保持／回退仍存在。人体与模型比例不同，也仍不能保证所有输入点绝对位置重合。
