# 交互站姿与语音切换（2026-10-23）

修改基于当前 release_1_0_1，保留现有 NPU 关键点映射、手腕、手臂深度和身体转向方案。未更换模型、相机或原始动画资源。Runner 只更新外置配置和检查，没有修改 UI 或 EXE。

## 已确认的原因和修改

1. 原 Humanoid 动画不仅涉及画面构图：在实际模型上采样 HeadPatIdle 时，Hips 高度由约 0.90 降到约 0，腿部肌肉曲线也使双腿折叠。相机本身能容纳正常站姿。因此在 GestureTriggerReceiver 的交互模式 LateUpdate 中恢复模型导入站姿的 Hips 高度和下半身旋转，上半身继续播放原有动画。跟随模式完全释放此约束。代价是交互回应中的髋部/腿部动作被固定为站立；上半身、表情和手势触发保留。
2. ASR 最终结果增加两个精确口令，经原有本地 UDP 39544 切换 motion_bridge 的唯一模式状态，不引入第二套模式。切换时暂停/恢复 DialogueSession，隐藏/恢复 Unity 和新输出的识别字幕。进入动捕立即取消当前本地回答、TTS 与播放；保留会话历史，恢复后接收新问题，不续播被打断回答。
3. 串口屏辅助程序原先会重复发送最后模式，每次重发都会再次应用，可能覆盖语音选择。现在重发只确认当前模式，每次真实按钮事件产生新序号；重复按同一个按钮也能切回来。辅助程序从确认消息学习当前模式，PC 桥接器重启后可恢复最后确认模式。屏幕协议仍是 @MODE=follow / @MODE=interact，CRLF 结尾。
4. 语音服务每 0.2 秒查询桥接器实际状态，按钮切换也同步控制字幕和助手。命令等待确认或失联超过 1.5 秒时暂停字幕/助手，ASR 继续。桥接器恢复后自动同步。Unity 后启动时，后续字幕会重新附带显示状态。

## 模式行为

| 触发 | 数字人 | ASR | 新字幕 | 助手 |
| --- | --- | --- | --- | --- |
| “跟着我的动作”或串口 follow | 动捕 | 保持监听 | 隐藏 | 暂停并停止当前播放 |
| “跟我聊天”或串口 interact | 全身站立，可摸头/捧脸/拥抱 | 保持监听 | 恢复 | 允许回答新问题 |

独立说完整口令，允许空白和标点；以云端 ASR 的最终文本为准，不做模糊匹配。口令不会提交给助手，重复的同一最终结果不会重复提交。普通句子、否定句、包含口令的长句不触发切换。初始模式仍由 Runner 选择；初始 follow 时安静监听属于预期。

语音对话总开关必须开启，才允许恢复助手。关闭总开关时，口令仍能切换模式与字幕，但不会开启付费对话。这保留 Runner 原有的显式控制。语音模式切换不重启 ASR、不清空聊天记忆；Runner 上直接开关语音服务仍遵循原有重启行为。

## 启用当前修改

1. Runner 中停止数字人与语音两个服务，再点击“重新读取配置”；或停止服务后退出并重开 Runner。目录仍为桌面 AI-Humen-Runner-v1.4.1-win-x64。
2. 数字人 Runtime 选择 `D:\FudanMicro\AAAAAnew\runtimeapp\release_1_0_1\AI_humen\AI_humen`；语音 full 选择 `D:\FudanMicro\AAAAAnew\runtimeapp\release_1_0_1\yolov8-pose+yolov8-face+yolov8-finger_full`。保持“语音字幕”和“语音对话”开启，启动两项服务。
3. Unity 打开该 1.0.1 内的 `pc\unity\DigitalManAvatar`，停止 Play，等待编译成功后重新 Play。**独立播放器需从此工程重新构建**；只重启旧 EXE 无法加载新的 C# 代码。
4. 将本 runtime 的 `yolov8-pose+yolov8-face+yolov8-finger_board/tools/uart_mode_bridge.py` 覆盖到开发板实际运行包的 `tools/uart_mode_bridge.py`，停止并重新运行板端启动脚本，使辅助进程加载新脚本。full 里的同名文件也已同步。**无需重新编译/替换 NPU 可执行文件、模型或串口屏工程。**板端的 IP 选择和其他启动参数沿用现状。
5. 语音服务启动日志应有 `[VOICE MODE voice-mode-20261023]`；说口令后有 `requested follow/interact`，确认后有 `follow ... paused` 或 `interact ... enabled`。数字人日志仍应保留此前手腕/深度/身体转向标记。

旧板端辅助脚本的心跳不会覆盖新 PC 端语音模式，但再次按相同模式按钮时可能没有新序号，因此仍需完成第 4 步，才能保证反复混用语音和按钮。

手动启动时，在 full 目录下执行以下命令；不要与 Runner 的语音服务同时运行。PythonExe 请替换为本机已装 websocket-client 的可用 Python，原有私有配置沿用：


motion_bridge 继续使用之前验证的 Runner/启动参数，保留 UDP 39544 模式控制。手动启动必须配合新版 bridge；语音服务无法绕过未运行的桥接器直接驱动 Unity。
